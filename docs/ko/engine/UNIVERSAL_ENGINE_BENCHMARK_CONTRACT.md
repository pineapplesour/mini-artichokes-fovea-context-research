# 보편엔진 공식 벤치마크 계약

상태: **규범적 문서**
기준일: 2026-07-24

이 문서는 보편엔진의 최종 목적, 평가 데이터, 비교 조건, 채점 방식과
금지된 과적합을 고정합니다. 벤치 러너, 엔진 구현 및 결과 보고가 이 문서와
충돌하면 저장소 루트 `AGENTS.md`와 이 문서의 최신 기준을 우선 확인해야
합니다. 아래의 과거 Beta6/DB 목록은 호환·확장 평가 자료이지 최종 구조를
고정하지 않습니다.

## 0. 현재 최상위 승격선

현재 첫 번째 정량 목표는 해시로 고정된 동일 619문항 보기 제거·주관식
벤치에서 봉인된 direct/no-DB Plain Codex를 이기는 것입니다.

| 기준 | 정답 | 오답 | 미해결 | 전체 정확도 |
| --- | ---: | ---: | ---: | ---: |
| Plain Codex (`gpt-5.6-luna`, no DB) | 393 | 218 | 8 | 63.4895% |
| 최신 Universal v3 후보 | 367 | 212 | 40 | 59.2892% |

핵심 달성 조건은 같은 619문항과 채점기로 393개보다 많이 맞혀 정확도
63.4895%를 넘는 것입니다. 미해결률·지연·호출·토큰·비용은 반드시 함께
공개해 범용성과 지속가능성을 판단하며, 벤치별 수작업 라우팅·정답 누출로
만든 향상은 인정하지 않습니다. 최신 v3 후보는 정확도 기준을 넘지 못했으므로
승격되지 않았습니다.

619문항 구성은 법률 16, 한의학 37, 기독교 성경 91, 기독교 Provao 85,
이슬람 금융 86, 이슬람 AQA 3, 심리학 301입니다. 원래 객관식 945문항 중
473문항은 보기를 숨겨 주관식으로 전환할 수 있었습니다. 보기 없이 의미가
애매한 나머지 472문항 중 의미 보존 재작성 146문항만 폐쇄형 독립 판정으로
승인했고, 애매한 326문항은 벤치에 넣지 않았습니다.

여기서 `법률 16`은 전체 법률 벤치 수가 아니라 619문항 승격선에 채택된
LEET 부분집합입니다. LEET 원본은 언어이해 30문항과 추론논증 40문항, 총
70문항입니다. 이 중 1문항은 이미 전환 준비 상태였고, 나머지 69문항의 의미
보존 재작성 중 15문항이 추가 승인되어 언어이해 6문항·추론논증 10문항, 총
16문항이 고정 게이트에 들어갔습니다. 고유 정답을 안전하게 보존하지 못한
54문항은 삭제한 것이 아니라 게이트 밖에 유지합니다.

별도의 판례 기반 법률 벤치는 고유 과제 3종을 10개 의미 보존 variant로
실행합니다. 따라서 정본 법률 범위는 시험문항 기준 70개와 별도 E2E 과제
3종/실행 variant 10개입니다. 양양 hard-retrieval 벤치의 query 2개는 E2E의
양양 variant 2개와 같으므로 새 문항으로 중복 집계하지 않습니다. 또한 전체
레거시 실행 registry는 객관식 원본 945문항과 원래부터 단답형인 불교
290문항을 합친 1,235문항입니다. 그러나 2026-07-24 사용자가 지정한 이슬람
공식 문제집 전체를 재감사한 결과, 기존 registry가 AQA 4문항 파생본을 전체
원본으로 잘못 간주했습니다. AQA20, BYU16, Cambridge32를 복원한 확인된 시험
인벤토리는 1,299문항입니다. 승인된 전환 619문항과 불교 290문항을 합한
909문항은 과거 주관식화 가능 범위이며 새 보기 공개 기준점과는 다릅니다.

예정된 보기 공개 기준점은 시험 1,299문항과 법률 variant 10개 전체를 격리된
Plain Codex solver 1회에 파일로 제공합니다. solver는 완전한
`answers.jsonl` 하나를 만들고, 별도의 Codex grader 1회가 이 파일과 모든
비공개 정답·rubric을 받아 `grades.jsonl`을 만듭니다. 과거 답은 재사용하지
않고 누락 행만 별도 호출로 보충하지 않습니다.

## 1. 최종 목적

최종 목적은 모든 실용적 종류의 문제를 빠르고 높은 정확도로 푸는 **하나의
범용 답변 엔진**입니다. “Codex를 요소로 쓴다”는 것은 Codex가 핵심 문제해결
구성요소인 후보가 Plain Codex의 정확도를 이긴다는 뜻입니다. 현재 연구는
(1) direct Codex에 Codex가 고르는 도구·스킬을 연결하는 방식과 (2) Codex
위에 범용 하네스를 얹어 반복·검증·산출물·평가 등 알고리즘적 견고성과
구조적 이점을 얻는 방식입니다. 데이터베이스와 Beta6는 선택적 비교·도구이지
보편엔진의 필수 단계가 아닙니다.

Gemma에 한정하지 않습니다. `codex exec`를 포함한 다른 provider/model도
사용할 수 있습니다. 단, 엔진 효과를 주장하는 한 비교 안에서는 provider,
정확한 model ID, reasoning effort, decoding, token budget, timeout 및 retry를
동일하게 고정해야 합니다. 서로 다른 모델의 결과로 엔진 우위를 주장할 수
없습니다.

## 2. 비교 arm

모든 승격 평가는 최소한 같은 문제에 대한 Direct와 Candidate를 실행합니다.
Beta6와 DB arm은 해당 가설을 검사할 때만 추가합니다.

| Arm | 모델 | DB | 실행 경로 |
| --- | --- | --- | --- |
| Direct | 동일 모델 | 없음 | 중립적인 공통 출력 계약만 사용 |
| Candidate | 동일 모델 | 없음 또는 선언된 선택 도구 | 새 Codex 중심 범용엔진 |
| Beta6 (선택) | 동일 모델 | 해당 벤치 DB | 과거 source-grounded 비교 |
| DB ablation (선택) | 동일 모델 | 선언된 동일 snapshot | 도구 효과 진단 |

시험 벤치 러너가 어떤 DB를 마운트할지 아는 것은 허용됩니다. production
엔진이 질문 내용이나 도메인을 보고 별도 로직을 선택하는 것은 허용되지
않습니다.

이는 수작업 도메인/문항 라우팅과 지엽적 예외를 금지하는 규칙입니다.
도메인 중립적인 planner·verifier·구조 선택기는 서로 다른 과제에서 Plain
Codex보다 지속적인 정확도 이점을 증명하면 연구·승격할 수 있습니다.

## 3. 절대 금지 사항

다음 구현은 점수가 올라도 보편엔진 성과로 인정하지 않습니다.

- 특정 키워드, 문제 문구, 벤치 ID, 정답, 판례번호 또는 정답 선택지를
  production 코드·프롬프트·랭킹·라우팅에 넣는 행위
- `if islam`, `if christian`, `if tcm`과 같이 도메인에 따라 검색, 추론,
  top-k, threshold, reranker, context budget 또는 답변 방식을 바꾸는 행위
- 벤치마다 별도의 동의어 사전, query rewrite 규칙 또는 정답 유도 prompt를
  두는 행위
- 정답 문구가 후보에 포함됐다는 이유만으로 검색이나 전체 답변을 PASS로
  처리하는 행위
- 데이터셋별로 유리한 모델을 선택하고 이를 하나의 보편엔진 성과로 합치는
  행위
- 기존 `AI :` 답변, 해설 또는 gold를 모델 입력에 노출하는 행위

DB별 adapter는 저장 형식과 공통 evidence schema를 기계적으로 변환하는
역할만 할 수 있습니다. 의미 기반 검색 전략, 가중치, prompt 또는 판단
정책은 모든 DB에 동일해야 합니다.

## 4. 확장·회귀 벤치 목록

이 절의 복원된 1,299문항 원본 목록과 법률 검색 과제는 추가 범위·회귀
평가용으로 보존합니다. 레거시 실행 registry는 1,235문항이었습니다. 현재
최상위 고정 승격선은 후속 승격이 명시되기 전까지 0절의 619문항 주관식
벤치입니다.

### 4.1 법률

법률 벤치는 하나의 고정 질문이 아닙니다. 의미를 유지한 여러 표현과 별도
held-out paraphrase로 실행합니다. evaluator의 판례번호와 정답은 엔진에
노출하지 않습니다.

#### 카카오톡/텔레그램 유심 접근

질문 의미: 수사기관이 피의자의 유심을 분리하여 공기계 등에 삽입하고,
피의자의 카카오톡·텔레그램 계정에 로그인하여 증거를 수집한 행위의 적법성.

최종 답변에 다음 판례 **모두가 실질적인 법리 근거로 사용**되어야 합니다.

- 서울행정법원 2025. 1. 21. 선고 2024구합65355 판결
- 서울중앙지방법원 2021. 8. 12. 선고 2020고합886 판결
- 서울고등법원 2022. 7. 21. 선고 2021노1520 판결

PASS에는 유심 분리·재삽입, 다른 단말기 인증/로그인, 계정 접근, 영장 범위,
전자정보 압수 및 위법수집증거·증거능력에 관한 올바른 적용이 필요합니다.
판례가 수백·수천 후보 중에 존재하거나 판례명만 나열된 것은 PASS가
아닙니다.

#### 군대 키 관리

질문 의미: 군 시설 또는 군 조직의 열쇠를 어떻게 보관·관리해야 하는지.

- 기본 목표 판례: 수원지방법원 2025. 1. 16. 선고 2023구합75301 판결
- 위 판례가 아니더라도 군대 키 관리에 관한 동등하고 올바른 판례를 실제
  근거로 사용하면 허용합니다.
- 답변은 이원화·분리 관리, 보관, 인수인계, 점검, 잠금 또는 관련 통제
  원칙을 정확히 설명해야 합니다.
- 사람의 신장, 키 성장 등으로 의미가 이탈하면 실패입니다.

#### 양양 사건

질문 의미: 김진하 양양군수 사건에서 뇌물을 준 민원인의 나이.

대상 판결은 이름과 지역이 마스킹되어 있으므로 단순 문자열 검색만으로는
연결하기 어렵습니다. PASS는 마스킹된 판결을 근거로 민원인 `D(여, 64세)`를
맞힌 경우입니다. 근거 없는 추측은 정답 숫자가 같아도 end-to-end PASS가
아닙니다.

## 5. 원본과 중복 정책

### 5.1 법학적성시험

Wikia 글 `LawKey AI 2026년도 법학적성시험 벤치마킹 결과 공유`의 첨부
`2026년도 법학적성시험.zip`을 사용합니다. 정본 ZIP SHA-256은
`6c2e7ff3255fa0336928a52f3c5dcda7f3b58efa24fa9486359a41c100cb3828`입니다.

- 언어이해 30문항과 추론논증 40문항을 모두 포함합니다.
- 언어이해의 공통 제시문은 해당 묶음의 각 문항 prompt에 복제하여 각 case를
  독립적으로 실행할 수 있게 합니다.
- 공개 manifest에는 제시문, 질문, 선택지만 둡니다. 첨부에 기록된 과거
  `AI :` 답과 `정답 :` 표시는 입력에서 제거하고, 정답 선택지 ID는 private
  scorer manifest에만 둡니다.
- 오답 통합본 36문항은 과거 AI 결과의 진단 자료일 뿐 별도 문항으로
  중복 집계하지 않습니다. 해당 과거 설정은 model/provider/decoding이
  불명확하므로 통제된 3-arm 결과로 간주하지 않습니다.
- Wikia post/attachment ID, 원본 파일별 SHA-256 및 분리 검증은
  `benchmarks/lawkey_leet_2026/source_audit.json`에 보존합니다.

### 5.3 불교

Wikia `불교 벤치마크.zip`의 290문항 단답형 자료를 그대로 사용합니다.
객관식 선택지를 인위적으로 만들지 않습니다.

- 질문만 입력합니다. 기존 `AI 답변`과 gold는 입력에서 제거합니다.
- 모든 시험 벤치가 공유하는 구조화 출력의 `finalAnswer` 값만 채점합니다.
- JSON decoding 이후의 Unicode 문자열이 gold 문자열과 완전히 같아야
  정답입니다. 동의어, 부분 일치, 한자 생략, 괄호 생략 및 부분점수는
  허용하지 않습니다.

### 5.4 한의학 50/64

내용 대조 결과는 다음과 같습니다.

- Wikia 64 중 1교시 1~22번은 현재 p1-50 manifest의 1~22번과 같은
  문항입니다. OCR 손상으로 문자열은 다르지만 교시, 번호, 문제 본문과
  선택지가 대응합니다.
- Wikia의 2~4교시 42문항은 p1-50과 다른 문항입니다.
- 따라서 두 공식 묶음을 모두 보존하며 고유 문항 합집합은 92개입니다.
- 보고서에는 `p1-50`과 `wikia-64` 점수를 각각 남깁니다.
- 전체 고유문항 aggregate에서는 겹치는 22문항을 한 번만 셉니다.
- 중복 문항은 가능하면 Wikia의 깨끗한 텍스트를 canonical prompt로 삼고,
  두 원본 ID를 provenance로 보존합니다. 정답은 공식 정답표로 검증합니다.

## 6. 채점과 보고

- 객관식의 주 지표는 공식 선택지 ID exact accuracy입니다.
- 불교의 주 지표는 위에서 정한 엄격한 문자열 exact accuracy입니다.
- 법률의 주 지표는 private oracle에 따른 최종 답변의 판례 사용, 법리 적용,
  사실관계 연결과 근거성입니다. retrieval recall은 별도 진단일 뿐 최종
  PASS를 대신하지 않습니다.
- 모든 결과는 영역별 점수와 전체 고유문항 macro/micro 결과를 함께
  공개합니다. 낮은 영역을 전체 평균으로 숨기지 않습니다.
- 비용, latency, failure rate, parse-valid rate, retrieval/source grounding,
  calibration과 robustness는 별도 지표로 기록합니다.
- 실제 실행 artifact에는 benchmark version, DB snapshot/digest, provider,
  model ID, model configuration, prompt/output, seed, retry와 scorer version을
  내구성 있는 경로에 저장합니다.

보편엔진이 원본 모델과 beta6를 모두 이긴 동일 모델 비교가 없으면 최종
목적을 달성했다고 주장할 수 없습니다. raw selector 개선만으로도 최종
성공을 주장할 수 없습니다.

## 7. 변경 통제

문항을 삭제·교체하거나 정답, 중복 판정, 평가 형식 또는 금지사항을 바꿀
때는 원본 provenance와 hash를 남기고 사용자 승인을 받아야 합니다. 실패한
문항을 조용히 제외하거나 엔진에 유리한 부분집합만 최종 점수로 제시할 수
없습니다.
