# 메모리 엔진 참고 자료 및 평가판 참고 사항

최종 업데이트 날짜: 2026년 5월 15일(KST)

이 폴더는 엔진팀의 시작 맵입니다. 프로젝트 아이디어, 이전 베타-6 강의, 테스트할 가치가 있는 외부 저장소를 수집합니다. 여기에는 자동으로 수락되는 항목이 없습니다. 모든 아이디어는 이 저장소의 벤치마크와 소스 창 계약을 통과해야 합니다.

## 이 노트가 존재하는 이유

이 프로젝트는 좁은 검색 위젯이 아닌 완전한 메모리 엔진을 구축하고 있습니다. 의도된 시스템은 지저분한 실제 말뭉치를 수집하고, 원본을 보존하고, 연대기와 참조를 이해하고, 전문가 수준의 회상으로 증거를 선택하고, 청구 카드와 소스 창을 통해 답변을 감사할 수 있도록 만들어야 합니다.

아래 참고 사항은 엔진 작업이 팀 간에 분할될 때 잊어서는 안 되는 시험 지침을 보존합니다.

- 베타-6은 내부 구현이 최종적이기 때문이 아니라 작성하기 전에 증거를 선택하고 검사 가능한 아티팩트를 생성했기 때문에 현재 기준선입니다.
- 단일 검색 패스에서 중요한 축이 누락되는 경우가 많기 때문에 적용 범위 패치가 필요합니다.
- 하나의 잘못된 바인딩으로 인해 전체 답변이 손상될 수 있으므로 중복 수렴이 필요합니다.
- 실제 파일은 시간, 슬라이드, 대본, 이미지, 반복 강의에 걸쳐 서로 참조하므로 트리/그래프 메모리가 필요합니다.
- 잘못된 기록/OCR/테이블 구문 분석으로 인해 복구할 수 없는 다운스트림 오류가 발생하므로 수집은 별도의 사후 고려가 아닌 메모리의 일부입니다.
- 벤치마크는 팀이 알려진 사례를 암기하는 대신 일반적인 능력을 입증할 수 있도록 다양하고 순환되어야 합니다.

## 보존해야 할 프로젝트 소유 아이디어

### Hit-Thunder 적용 범위 패치

참고: https://github.com/pineapplesour/Hit-Thunder

아이디어를 엔진 루프로 사용해야 합니다.

1. 사용자 목표를 해석합니다.
2. 필요한 적용 범위 축을 열거합니다.
3. 선택한 증거를 각 축에 첨부합니다.
4. 누락되거나 약하거나 모순되거나 해결되지 않은 축을 감지합니다.
5. 다시 검색/점검해야 합니다.
6. 모든 축이 만족되거나 명시적으로 없는 경우에만 중지합니다.

필수 아티팩트: `axes`, `satisfied`, `weak`, `missing`, `followupSearches` 및 `explicitAbsence`가 포함된 `coverageReport`.

### 미니 아티초크 Redundant Convergence

참고: https://github.com/pineapplesour/mini-artichokes

위험성이 높은 결정에는 독립적인 패스를 사용해야 합니다.

- 시험 범위/날짜 추출;
- 반전되거나 대체된 진술;
- 인용 범위 일치;
- 파일 간 참조 확인;
- 추천 최고의 선택;
- 다중 모달 사본-슬라이드 바인딩.

통과에 동의하지 않는 경우 불일치를 보고합니다. 하나의 자신감 있는 대답 뒤에 그것을 숨기지 하지 않아야 합니다.

## 잊지 말아야 할 이전 베타-6 교훈

- 전면 감사 사항: 이슬람/TCM은 일반적으로 1,200명의 후보자를 감사하고 100명의 소스를 선택합니다.
- 늦은 키워드 기아는 실제 버그였습니다. 광범위한 첫 번째 라운드가 경계를 채우고 보다 구체적인 두 번째 라운드 용어를 기아시킬 수 있습니다.
- 키워드 라운드를 낮추면 증거 구성이 크게 바뀔 수 있습니다. 이는 단지 레이턴시 튜닝이 아닙니다.
- 선택기 작업자 수만으로는 대기 시간 목표를 충족할 수 없습니다. 가장 느린 배치는 단단한 바닥을 설정합니다.
- 핫 캐시 앱 경로 증명은 콜드 대기 시간 증명이 아닙니다.
- 프롬프트 모양 변경이 승격되기 전에 프롬프트 크기 원격 분석이 있어야 합니다.
- 중복, 프롬프트 크기, 시간 초과 또는 소스 종류 게이트를 확인할 때 그럴듯해 보이는 선택기 변형이 실패했습니다.
- 청구 건수만으로는 충분하지 않습니다. 후보/인용 주장 분할 및 소스 창 강조표시는 UI에서 확인되어야 합니다.
- 작성자는 요약만으로 답변하지 않고, 엄선된 원본 증거를 바탕으로 답변해야 합니다.
