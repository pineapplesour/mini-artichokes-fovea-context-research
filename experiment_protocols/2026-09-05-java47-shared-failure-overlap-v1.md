# Java47 shared-failure overlap: fixed before both new calls

This is result-informed development on the same complete official Java47 track,
not untouched-task confirmation. Preserve all earlier studies, including the
invalid Generic-B source-scope result. Neither new arm replaces that candidate.

## Why this structure

Full test-case replays of P/G/R reproduced their original47-task outcome vectors
(7,7,10 successes). Among unresolved tasks, only `pig-latin` showed observed
test-case union coverage beyond the best individual candidate; its union covered
all22 tests. Missing or nonaligned case reports are unknown, so this is not a
universal impossibility claim about recombination. Nevertheless there is little
observed support for pure donor fusion as the next large-gain hypothesis.

The new treatment instead aligns failures across the Plain and Graph/ordinary
lineages. Repeated violated requirements guide general repairs while supported
obligations are retained; exclusive partial successes are secondary donors.
Agreement among failed candidates is not correctness. Graph and its subsequent
repair are one ancestry group, not two statistically independent votes.

## Fixed comparison

- Include all47 task IDs at Aider commit
  `7e0611e77b54e2dea774cdc0aa00cf9f7ed6144f`, unchanged official tests and scoring.
- Reuse exactly the existing P/G/R candidates. Both new arms start from the same
  ordinary-repair patch, with identical patches, source snapshots, case-status
  matrices, bounded assertion messages and derived overlap fields. Generic repair
  is unrestricted and may compute or use the same overlap relations.
- New arms: `shared_failure_v1_generic` and `shared_failure_v1_overlap`.
  Run generic first, then overlap, sequentially. Each gets one Luna/medium agent
  execution, default service tier,900-second agent cap and1800-second evaluator
  cap, through the approved Codex account. No per-task model calls.
- Each system has four logical agent executions and four implementation
  candidates: P/G/R plus its final repair. The previous probe author and all
  probe-study final candidates are excluded from both inputs and costs.
- Both arms receive the richer authoritative failure feedback. Gains over the
  previous clipped-feedback experiments cannot establish an overlap effect;
  only this same-input contrast addresses the new policy comparison.
- Keep strict solution-file scope, unchanged evidence, complete47-row ledgers
  and normal agent completion. A scope violation or incomplete result is retained
  as ineligible, not repaired after scoring, imputed as zero, or replaced by a
  selected fresh draw. Both frozen calls remain planned; an invalid arm prevents
  a valid paired primary conclusion.
- Final selection order: final repair > ordinary repair > Graph > Plain, using
  complete task states only. Materialize and re-evaluate every system on all47
  tasks; do not count a union of individual test cases as a solved program.

## Endpoints and promotion

Primary: overlap-system minus generic-system solved task count and percentage
points. Also report paired rescues/harms, conditional exact tests, candidate-only
scores, actual output/input/cached tokens and aggregate agent execution time.
Equal caps do not imply equal realized compute; evaluator time is separate.
Do not treat47 task rows as47 independent agent sessions.

A realized lead is development evidence only. A strong claim requires fresh
paired model executions and transfer to another complete official track, with
the policy and budgets fixed before results. Audit actual source changes and
traces before attributing improvements to shared-failure repair. No new review
score is claimed from this protocol or from better feedback collection.
