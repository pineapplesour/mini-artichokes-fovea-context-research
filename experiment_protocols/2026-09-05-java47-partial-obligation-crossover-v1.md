# Partial-obligation crossover from a strong all-generic portfolio

## Hypothesis and scope

The preceding Java47 obligation-view portfolio completed18/47 versus22/47
for repeated generic repair. Do not repeat that weak comparison or select a
different generic result. A complete post-repair case diagnostic then found
four unresolved tasks for which the *generic A/B* passing-case union covers
the observed full case inventory. This is potential donor evidence, not four
new solutions. The original overlap candidate is excluded from the new solver
inputs, prefix, seed and compute accounting. All47 official tasks remain in
the endpoint; task identifiers do not determine the repair rule.

Test whether coverage-directed semantic crossover produces more complete
passing programs than strong generic feedback repair when both start from the
same strongest existing all-generic portfolio. A donor's passing obligation
must be localized in actual source, combined without invalidating supported
behavior, and checked against the specification. Copying whole failing
candidates or treating agreement as truth is insufficient. Shared failures
still require a synthesized general repair; crossover is not a rigid veto.

the actual mechanism rather than rerolling the same control.
