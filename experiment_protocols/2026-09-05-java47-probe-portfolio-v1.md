# Sibling study: heterogeneous overlap portfolio versus repeated generic repair

## Scope and chronology

This is a separately declared exposed-task development study, not a change to
the three-new-call independent-probe component comparison. It requires only
ONE additional whole-Java47 Luna execution, called Generic-B. Generic-A is
the already planned `probe_v1_generic` arm. No output is replaced or retried.

The study is specified after inspecting the overlap agent's completed code,
ledger and actual probe-execution trace, but before inspecting its official
task score, before either generic score exists, and before Generic-B is run.
The independent probe-author packet includes its disclosed pre-scoring ID-only
amendment. This is method development, not new-task or end-to-end confirmation.

## Scientific question and fixed six-execution systems

The user's target is an overlap-containing solver that outperforms a strong
same-budget alternative. A heterogeneous route need not itself dominate every
generic draw to contribute useful new coverage. Test that system question
against a genuine repeated-generic portfolio, not against a constituent that
the proposed union necessarily contains.

Both systems contain the original complete-track P/G/R executions and the same
independent probe-author execution. They then include:

- Heterogeneous: Generic-A and the overlap repair.
- Homogeneous: Generic-A and a fresh Generic-B repair.

Thus both systems count SIX logical Codex agent executions and FIVE source
candidate snapshots. The generator is computation, not a solution candidate.
The original component comparison still counts five executions per system.

Generic-B receives exactly the original ordinary seed and the same P/G/R
evidence, complete public source snapshots, frozen probes, replay helper and
generic prompt as Generic-A. It receives no result, code, ledger, score or
feedback from either final sibling. Its different artifact ID is provenance
only. Luna/medium, default tier, JDK17,900s agent ceiling and1800s evaluator
ceiling are unchanged. Record prompt/seed/evidence hashes and actual tokens,
agent time, and all verified outcome vectors. Equal ceilings are not identical
realized compute. No best-draw replacement or selected retry.

## Complete denominator, selectors, and estimand

Keep all47 official Java tasks in the existing frozen inventory. For each
system materialize a passing complete source snapshot with fixed priority
the differing route (Overlap or Generic-B) > Generic-A > ordinary > Graph >
Plain; if none passes, retain the differing route. Re-run the official suite
on both materialized systems and require their complete task vectors to match
the respective unions. This shared selector is not the new mechanism.

Primary: heterogeneous minus homogeneous system passes over all47, including
rescues/harms, percentage points, realized computation and exact paired tests
conditional on these agent executions. Also report each constituent and the
shared P/G/R+Generic-A floor. Do not test a union against its own constituent
as evidence of architectural superiority. Do not pool task-session counts
with independent tasks or with previous development protocols.

Positive net gain is a development lead, not sufficient for the final paper
goal. A lead needs independent paired sessions with newly generated probe
packets and evaluation on another complete official track. The ambitious
target remains +10/47, exceeding20 percentage points, against the SAME-BUDGET
generic portfolio, not just Plain. Do not promote an invalid, missing, tied,
or losing contrast. Failure of any required execution leaves this contrast
incomplete; existing valid component results are preserved separately.
